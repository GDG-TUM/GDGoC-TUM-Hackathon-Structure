# Buildathon Challenges

This folder contains challenge templates for the five GDG on Campus TUM tracks:

- Web Development
- Cloud Computing
- Mobile Development
- AI & Machine Learning
- Cybersecurity

At least two buildathon challenges will be announced each week in the official club groups. This folder gives members a home for track guidance and gives organisers a consistent format for publishing prompts.

## How to use the challenge files

- Open the file for your track.
- Read the full challenge prompt and announcement details.
- Follow the deadline and submission instructions from the official group.
- Do not assume a template is an active challenge unless it is marked **Open** in an official announcement.
- Organisers can copy a starter prompt, customise it and add a challenge title, deadline, deliverables and judging criteria.

## Recommended announcement template

```markdown
## [Challenge title]
- **Status:** Open / Closed / Coming soon
- **Track:** [Track]
- **Published:** [Date]
- **Deadline:** [Date, time and timezone]
- **Team format:** Individual / Team of [number] / Either
- **Difficulty:** Beginner / Intermediate / Advanced

### Problem
[What problem should participants address?]

### Task
[What should participants build, test, analyse or demonstrate?]

### Requirements
- [Requirement 1]
- [Requirement 2]
- [Requirement 3]

### Deliverables
- [Repository, demo, screenshots, short write-up or other requested output]

### Evaluation
- Problem understanding
- Functionality and technical quality
- Usability, accessibility or security as relevant
- Creativity and clarity of explanation

### Submission
[Submission link or method]

### Rules and support
[Originality, permitted tools, safe testing boundaries and where to ask questions]
```

## Challenge design principles

- Keep each challenge achievable within its announced time limit.
- State the required outcome and evaluation criteria clearly.
- Welcome beginners while offering optional stretch goals.
- Avoid requiring paid tools unless a free alternative is available.
- Never ask participants to use real sensitive data or test systems without permission.
- Give feedback that helps members improve, not only a score.
