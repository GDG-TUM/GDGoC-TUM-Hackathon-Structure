# Pitch & Demo Checklist

Use this checklist before a showcase, hackathon submission or practice pitch.

## Pitch story
- [ ] The problem is clear and specific.
- [ ] The target users or beneficiaries are identified.
- [ ] We explain why the problem matters.
- [ ] The solution is understandable without specialist knowledge.
- [ ] We explain what makes our approach useful or different.
- [ ] We connect the project to intended impact where relevant.
- [ ] We state what we have actually built and tested.
- [ ] We acknowledge limitations and next steps.

## Demo readiness
- [ ] The main user flow works from a clean start.
- [ ] The demo has been tested on the presentation device/network.
- [ ] Test accounts and sample data are ready and contain no sensitive information.
- [ ] No passwords, tokens or private keys are visible.
- [ ] A backup plan exists (screenshots or a recorded demo).
- [ ] Each presenter knows their part and the handoff.
- [ ] The team has practised within the time limit.

## Project readiness
- [ ] Repository has a clear README and setup instructions.
- [ ] Dependencies and environment requirements are documented.
- [ ] Known bugs and limitations are listed.
- [ ] Third-party assets, libraries and data sources are acknowledged.
- [ ] Submission requirements and deadline have been checked against the official announcement.

## After presenting
- [ ] Record questions and feedback.
- [ ] Identify the highest-priority improvement.
- [ ] Agree on who owns the next action.
